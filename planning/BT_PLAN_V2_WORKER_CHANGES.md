# BT Plan V2 Worker Changes

## Review Summary

`docs/BT_Plan_v2.md` is a meaningful improvement. It identifies the stronger launch persona: a working board member of an established California nonprofit, not a beginner founder who needs a definition of "board."

The biggest change is product shape. The site should become a boardroom field manual: a practical tool for preparing for meetings, reading board packets, asking better questions, spotting red flags, reviewing budgets/audits, and knowing when an issue should go to counsel.

## What Should Change Before Workers Start

### 1. Add A Product/IA Worker

Why:

The old plan lets each worker infer navigation from a generic article library. V2 needs one owner for the boardroom structure.

New ownership:

- Navigation labels.
- Route map.
- Two-path model:
  - working board
  - starting a nonprofit
- CTA map.
- Contextual NPO Lawyers referral strategy.

### 2. Replace Downloads Worker With Tools/Labs Worker

Why:

V2's best ideas are not just downloadable files. They are productized tools:

- Board Packet Lab.
- Board Question Bank.
- Board Red Flags.
- Mature Board Self-Assessment.
- Board Packet Review Sheet.
- Budget Deviation Worksheet.
- Minutes Quality Scorecard.

This worker should own the tools experience, not just a downloads grid.

### 3. Add A California Rules And Legal-Escalation Worker

Why:

V2 makes California specificity a major advantage. That creates legal-content risk and attorney-review needs.

This worker should own:

- California Board Rules section.
- Audit threshold and audit committee content.
- Form 990 and public disclosure content.
- Attorney General Registry topics.
- Compensation/conflict/records topics.
- `When to call counsel` blocks.
- Source verification and attorney-review flags.

Official sources should be preferred over secondary summaries. Current planning sources confirm that California AG materials describe audit obligations at the $2 million total/gross revenue level for covered charities, and IRS instructions use the $200,000 gross receipts / $500,000 total assets thresholds for full Form 990 filing, subject to exceptions.

### 4. Change The Homepage Worker

Old job:

- Build a homepage with featured articles, beginner path, downloads, and training.

New job:

- Build a boardroom problem picker.
- Build `Prepare for Your Next Board Meeting`.
- Lead with the mature board promise.
- Include Strategy, Safety, Audit.
- Push tools and scenarios before latest articles.

### 5. Change The Article/Scenario Worker

Old job:

- Build article and scenario templates.

New job:

- Build meeting-ready field manual templates.
- Every article should include:
  - use this when
  - boardroom problem
  - rule
  - questions to ask
  - what not to do
  - documents that matter
  - minutes should show
  - red flags
  - when this becomes legal
  - related tool
  - training CTA

### 6. Expand The Design System Worker

The design worker should build the specific field manual components:

- Boardroom Rule.
- Ask This.
- Do Not Do This.
- Minutes Should Show.
- Legal Escalation.
- California Note.
- Red Flag.
- Decision Trail.
- Authority Map.
- Board Packet Mode button.

The palette should move toward the V2 functional system:

- Ink for seriousness.
- Warm paper for reading.
- Slate for governance.
- Teal for finance/audit.
- Copper for safety/risk.
- Burgundy for conflicts/legal escalation.
- Brass for tools/active states.

### 7. Keep Training Worker, But Make CTAs Contextual

The training worker should not just build "register for webinar." It should build context-aware prompts:

- Audit article -> audit committee / governance policy help.
- Compensation article -> founder/executive/insider compensation help.
- Bylaws article -> bylaws no longer match practice.
- Risk article -> safety/youth protection review.

## Revised Worker List

1. Foundation and Content Schema.
2. Product IA and Routing.
3. Design System and Boardroom Components.
4. Homepage and Next Meeting Experience.
5. Field Manual Tools and Labs.
6. Meeting-Ready Articles and Scenarios.
7. California Rules and Legal Escalation.
8. Training and Conversion.
9. SEO, Accessibility, and QA.
10. Hostinger Deployment.

## Launch Priority

Build these first:

1. Homepage with boardroom problem picker.
2. `/next-meeting`.
3. `/tools/board-packet-lab`.
4. One meeting-ready article.
5. One mature-board scenario.
6. One California rules page.
7. Training overview and request path.

This validates the new concept before filling the full library.

## Risks To Manage

- Legal specificity can overstate obligations if not sourced and reviewed.
- The mature-board track should not erase startup/founder content; it should simply become the more prominent path.
- Tools can sprawl. Keep launch tools high value and static.
- "California-specific" must be helpful without becoming legal advice.
- The homepage still needs all four original actions visible.

## Recommendation

Adopt V2 as the implementation direction before workers start. The old plan is still useful for content inventory and deployment, but the worker kickoff should use `planning/PARALLEL_WORK_PLAN.md` as revised by this review.
